# Анализ услуг ТО компьютерной техники

AI-ассистент разбирает прайсы, договоры, визуалы и сайты сервисных центров: состав услуг, покрытие техники, SLA, цены и риски для заказчика.

## Что анализируется

- **Текст** — прайс, коммерческое предложение, абонентский договор, описание услуг на лендинге
- **Изображение** — прайс-лист, баннер сервиса, фото мастерской, чек-лист работ, скриншот страницы услуг
- **Сайт** — только указанная страница: контент, скриншот и внутренние ссылки с этой страницы
- **Дерево ссылок** — история собранных URL в файле `.config`: иерархия, ручной выбор, отметка уже разобранных
- **История запросов** — последние 10 анализов (текст / изображение / парсинг)

Структура ответа по тексту/сайту:

| Поле | Смысл |
|------|--------|
| `service_types` | Виды услуг (диагностика, ремонт, профилактика, выезд, абонентское ТО) |
| `equipment_coverage` | ПК, ноутбуки, серверы, периферия, сети |
| `sla_and_process` | Сроки, гарантия, этапы заявки |
| `pricing_notes` | Цены, пакеты, что не входит |
| `strengths` / `gaps` | Сильные стороны и пробелы/риски |
| `recommendations` | Как усилить пакет ТО |
| `overall_score` | 0–10 полнота и прозрачность оффера |
| `summary` | Краткое резюме |

## Быстрый старт

```bash
cd CompService-Monitor
python -m venv venv
# Windows:
venv\Scripts\activate
pip install -r requirements.txt
```

Создайте `.env` по шаблону `env.example.txt`:

```env
PROXY_API_KEY=your_proxy_api_key_here
OPENAI_MODEL=gpt-4o-mini
OPENAI_VISION_MODEL=gpt-4o-mini
LOG_LEVEL=DEBUG
```

Запуск:

```bash
python run.py
```

Веб-интерфейс: http://localhost:8000  
Swagger: http://localhost:8000/docs

Desktop (backend уже запущен):

```bash
pip install -r desktop/requirements.txt
python desktop/main.py
```

Сборка exe: `python desktop/build.py` → `desktop/dist/CompServiceMonitor.exe`.

## Сбор ссылок и дерево страниц

Парсер **не обходит весь сайт**. На текущей странице собираются внутренние ссылки того же домена (до 80, без файлов вроде PDF/картинок).

После успешного разбора:

1. Страница помечается как проанализированная.
2. Найденные ссылки сохраняются как дочерние узлы в `.config`.
3. В результате разбора и на вкладке **Сайты** (веб и desktop) показывается дерево: родитель — разобранная страница, дети — ссылки с неё.
4. Дальше парсите **вручную**: отметьте чекбоксами нужные URL и нажмите «Парсить выбранные». Автообхода нет.

Уже разобранные узлы выделены цветом и отмеченным чекбоксом статуса. Повторный разбор той же ссылки обновляет узел и дописывает новые дочерние ссылки.

История запросов (`history.json`) — это последние 10 AI-анализов. История ссылок — отдельное дерево в `.config`.

## Структура

```
CompService-Monitor/
├── backend/
│   ├── main.py
│   ├── config.py              # настройки + файловое логирование
│   ├── prompts.py             # промпты анализа услуг ТО
│   ├── models/schemas.py      # ServiceAnalysis, ParsedSiteNode, ссылки
│   └── services/              # parser, sites (.config), history, openai
├── frontend/
├── desktop/                   # PyQt6; сборка: desktop/dist/CompServiceMonitor.exe
├── .config                    # дерево собранных ссылок
├── history.json               # последние 10 запросов анализа
├── logs/                      # compservice.log, desktop.log
├── requirements.txt
└── env.example.txt
```

## Логирование

- Консоль: INFO и выше
- Файл `logs/compservice.log`: DEBUG, ротация 5 МБ × 5 файлов
- Desktop: `logs/desktop.log`
- В лог пишутся метод/путь/клиент, длительность, размер файлов, токены модели, traceback ошибок

Уровень: переменная `LOG_LEVEL` (`DEBUG`, `INFO`, `WARNING`).

## Требования

- Python 3.9+ (рекомендуется 3.12)
- Ключ [ProxyAPI](https://proxyapi.ru/)
- Chrome для парсинга сайтов
